# 甲方诉求深度转译与 UX/UI 根因诊断 (Root Cause Translation)

根据前述关于“需求转译”的原则，我们将甲方的口头表象诉求转译为底层的产品机制与 UX 交互解法：

---

## 需求转译矩阵 (From Voice of Customer to UX/UI Architecture)

```
┌───────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                     甲方诉求与深层 UX 根因转译全景                                     │
├────────────────────┬─────────────────────────────┬────────────────────────────────┬───────────────────┤
│ 甲方表层诉求       │ 实际发生的教学使用场景      │ 深层 UX / 交互痛点 (根因)       │ 推荐的专业重构解法 │
├────────────────────┼─────────────────────────────┼────────────────────────────────┼───────────────────┤
│ 1. “批量操作太麻烦” │ 课堂值日、全组背诵等集体奖惩 │ 缺少多选器、全选模式与快捷组操作 │ 教师端增加【批量模式】│
│                    │ 老师需逐一点击 40 次学生卡片 │ 导致严重的高频机械劳动          │ 支持按小组/全选一键赋分│
├────────────────────┼─────────────────────────────┼────────────────────────────────┼───────────────────┤
│ 2. “升了几十级还是 │ 学生连续获得加分升级，但卡片 │ 数值等级与外观形态脱节 (4张图) │ 重构成长阶梯：      │
│     那个鬼样子”    │ 视觉无明显变化，产生审美疲劳 │ 缺乏“小步快跑”的视觉阶段反馈   │ 微等级数值 + 晋升变身│
├────────────────────┼─────────────────────────────┼────────────────────────────────┼───────────────────┤

│     渴了困了有动作”│ 只有手动点击弹窗才有反应     │ 无法对非操作时间提供情绪价值   │ 困/渴/饿/活泼 气泡与动效│
├────────────────────┼─────────────────────────────┼────────────────────────────────┼───────────────────┤
│ 4. “烟花撒给谁看的 │ 学生加分或升级时，全屏撒花， │ 视线焦点分散，未做背景压暗，   │ 打造【C位高光聚焦 (Spotlight)】│
│     属于无效 UI”   │ 被奖惩的学生并未成为视觉核心 │ 属于“有动效但无层级”的无效设计 │ 背景压暗 + 焦点卡片放大居中  │

│     比谁宠物多”    │ 跨学科老师无法独立评价学生   │ 无法支撑长期赛季与多科目分类   │ 满级转生 + 学科宠物卡槽     │
├────────────────────┼─────────────────────────────┼────────────────────────────────┼───────────────────┤

│     QQ 邮箱同步”   │ 炫耀宠物成长与积分账单       │ 缺乏网络身份鉴权与跨设备云存储 │ 定义云端数据接口与账号体系  │
└────────────────────┴─────────────────────────────┴────────────────────────────────┴───────────────────┘
```
