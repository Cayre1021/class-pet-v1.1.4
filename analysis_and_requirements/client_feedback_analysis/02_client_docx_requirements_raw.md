# 甲方需求 Word 文档内容归纳与原始文本

## 原始需求点归纳（6 大核心模块）

1. **基础操作瓶颈**：
   - 教师日常加扣分缺乏高效的**“批量操作”**机制。

2. **宠物形态与成长反馈**：
   - 宠物形态过于单一，升级后外观变化不显著（“升了几十级还是那个样子”），缺乏持续的阶段性成就感。

3. **动态与日常交互（类 QQ 宠物）**：
   - 缺少日常生理状态（困、渴、乏、心情波动）；
   - 交互按钮缺少对应的骨骼/帧动作反馈，需要从“静态卡片头像”升级为“有生命力的动态宠物”。

4. **高光时刻全屏仪式感**：
   - 达到满级或关键里程碑时，需要有全屏级别的庆祝动画与荣誉宣告。

5. **机制革新：一人多宠（学科宠物/收集博物馆）**：
   - 放弃人为压制加分节奏的落后做法；
   - 允许单个学生培养多个宠物（如语文宠、数学宠、物理宠），以“谁解锁的满级宠物多”作为持续激励。

6. **UI 动效纠偏（有效 UI vs 无效 UI）**：
   - 消除屏幕中央盲目全屏撒花；
   - 加分/升级时必须做**“全屏暗化背景 + 主角居中置顶 (C位 Spotlight) + 烟花精准呼应”**。

7. **进阶架构诉求（云端化与带回家）**：
   - 远期支持接入云端数据库，支持通过账号（如 QQ/邮箱）将满级宠物数据同步/带回家中展示。
