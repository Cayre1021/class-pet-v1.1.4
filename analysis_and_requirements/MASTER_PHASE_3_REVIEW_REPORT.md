## 第一部分：老版本系统形态与交互基准

### 1. 技术栈与架构形态
- **前端与桌面**：React 18 + Vite + Tailwind CSS + Framer Motion，支持 Electron 桌面端离线运行与 Android 壳部署。
- **存储方案**：纯单机 `LocalStorage` 键值隔离，通过 `window.storage` 事件在同一台机器的浏览器标签页间同步。
- **现存最大架构短板**：**纯单机无后端**，数据无法跨设备漫游，无法支持学生回家登录，且数据面临被浏览器缓存清理的巨大风险。

### 2. 页面动线现状
- **统一入口 (`/`)**：提供大屏、教师管理、学生查询三大独立卡片。
- **班级大屏 (`/screen`)**：以网格排列全班宠物卡片，支持点击弹窗进行简单的“喂食/抚摸/AI对话”互动。
- **教师工作台 (`/admin`)**：先选单个学生，再点击右侧行为项赋分，缺乏批量模式。
- **学生查询 (`/student`)**：单人宠物查看与积分流水日志。

### 3. 资产与视觉现状
- **宠物体系**：8 类动物（鸟、兔、猫、鹿、狗、鱼、狐、仓鼠），每类 4 个静态 PNG 阶段。
- **视觉风格**：多邻国（Duolingo）糖果色立体按压风格。升级时虽有 Confetti 彩花，但**全屏盲目撒花，被操作的学生缺乏 C 位高光聚焦**。

## 第二部分：甲方素材多模态提取与交叉印证

通过解析 `宠物系统优化需求汇总.m4a`（7分31秒音频）与 `宠物系统优化需求汇总.docx`，比对出的核心事实如下：

1. **印证一致性**：Word 文档与录音对话完全同源。甲方提出改进的核心驱动力在于**一线真实课堂使用中暴露的“效率低、成长感弱、大屏缺乏生命力”**。
2. **核心情绪与关键诉求**：
   - 🔴 **效率痛点**：教师端批量赋分缺失，大班级操作极其繁琐。
   - 🔴 **视觉挫败**：“升了几十级还是那个鬼样子”，静态素材严重滞后于数值增长。
   - 🔴 **交互死板**：大屏宠物如同“静止头像”，缺乏类似 QQ 宠物的日常生理状态机（困了、渴了、趴地动画）。
   - 🔴 **动效失焦**：升级烟花撒在屏幕中央，被严厉批评为“不知道撒给谁看的无效 UI”。
   - 🟢 **机制破局（兰老师方案）**：拒绝人为卡控积分上限，全面推行**【一人多宠 / 学科宠物挂载体系】**（如语文宠、数学宠、物理宠），以“收集满级宠物数量”作为长期激励。
   - 🔵 **进阶远期诉求**：支持云端数据库，未来允许通过 QQ 号码/邮箱将宠物数据同步并带回家中。

## 第三部分：核心痛点根因转译与重构差距矩阵

| 序号 | 甲方反馈表象 | 真实使用场景 | 深层 UX 根因 | 第四阶段重构解法 |
| :---: | :--- | :--- | :--- | :--- |
| **01** | *“批量操作太麻烦”* | 集体背诵、值日等 40 人集体赋分 | 缺少多选器、全选模式与快捷组操作 | 教师端增加【批量模式 / 小组矩阵】，支持多选一键赋分 |
| **02** | *“升了几十级还是那个鬼样子”* | 学生持续加分升级，但形态无变化 | 数值等级与外观阶段严重脱节 (仅4张图) | 划分【微等级数值】+【关键晋升变身】，增加可挂载特效与专属徽章 |
| **03** | *“像 QQ 宠物一样渴了困了有动作”* | 课堂常态挂机展示，宠物长期静止 | 缺乏 Idle 状态机与非操作时间情绪价值 | 引入【生理状态机】：困/渴/饿/活泼 自动随机触发动作与气泡 |
| **04** | *“烟花撒给谁看的？属于无效 UI”* | 某位学生加分/升级时全屏撒花 | 缺乏视线引导与层级对比 | 打造【C位高光聚焦 (Spotlight)】：全屏暗化 + 目标卡片居中放大 + 烟花精准呼应 |
| **05** | *“一人可挂多宠物，比谁宠物多”* | 优等生早期满级后失去动力 | 单实体绑定导致成长上限被锁死 | 升级为【多宠物博物馆体系】：满级进入荣誉殿堂，支持开辟新学科宠物 |
| **06** | *“宠物带回家与 QQ 邮箱同步”* | 学生在家中设备查看并向家长展示 | 单机 LocalStorage 无法跨端漫游 | 架构升级为 Cloud-Ready 标准，定义清晰的云端实体与 API 接口契约 |

## 第四部分：第四阶段 (Phase 4) UX 重构方向与云端架构规划

### 1. UX 重构的三大核心模型推演
在第四阶段，我们将为系统设计出 **3 套差异化的 UX 方案**（对应我们之前探讨的多版本对比策略）：
- **方案 A（经典流畅版 - Standard Flow）**：保留多邻国活泼卡片风格，补齐批量多选、C位高光 Spotlight 与生理状态机。
- **方案 B（极速工作台版 - Power Grid）**：针对高频教师操作，采用左右分栏/紧凑数据网格，支持纯键盘快捷键赋分与多班级快速切换。
- **方案 C（沉浸式开放设计版 - Open Design Editorial & 3D Interactive）**：融合 Open Design 的帅气排版与拟真电子宠物生命感，打造殿堂级大屏展示与博物馆式多宠收集系统。

### 2. 云服务器就绪架构 (Cloud-Ready Blueprint)
为保证后续无缝联通云端数据库，数据实体将扩展为：
```typescript
// 扩展后的 Cloud-Ready 数据实体标准
export interface StudentProfile {
  id: string;                  // 学生全局 UUID
  accountKey: string;          // 关联的班级/教师 Key
  studentName: string;         // 学生姓名
  studentNumber?: string;      // 学号
  boundEmail?: string;         // 绑定的 QQ 邮箱 / 家长账号 (进阶带回家用)
  activePetId: string;         // 当前正在培养的主出战宠物 ID
  petMuseum: PetInstance[];    // 历史已解锁 / 满级退役的宠物资产博物馆
  totalPoints: number;         // 历史总积分
}

export interface PetInstance {
  petId: string;
  petType: string;             // 种类 (小狗/小猫/小鸟等)
  subjectType: string;         // 所属学科 (综合/语文/数学/物理等)
  level: number;
  exp: number;
  stage: number;               // 外观阶段 (1-4)
  unlockedAccessories: string[];// 解锁的配饰部件
  isMaxLevel: boolean;         // 是否已满级
  graduatedAt?: number;        // 毕业封存时间戳
  moodState: 'happy' | 'sleepy' | 'thirsty' | 'hungry' | 'sick';
}
```
