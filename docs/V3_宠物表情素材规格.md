# 宠物表情素材规格（B 路线：逐物种逐阶段出图）

> 用途：给「点击宠物 → 三个互动」提供表情图。由负责人把本文件交给豆包（工作区设为下面第 2 节的目录），产图后跑第 5 节的校验脚本验收。
> 现状：代码已支持"有表情图就换图、没有就只出气泡"，所以**素材可以分批交付**，缺哪张不影响运行。

## 1. 需要哪些表情

三个互动对应三种表情（文件名后缀固定）：

| 互动 | 表情后缀 | 情绪 | 视觉要点 |
|---|---|---|---|
| 摸摸 | `pat` | 舒服、眯眼、被摸头 | 眼睛弯成弧线、脸颊微红、耳朵/毛发微微下垂 |
| 喂食 | `feed` | 满足、嘴里有食物 | 嘴巴鼓起或叼着小零食、眼睛亮、脸略圆 |
| 玩耍 | `play` | 兴奋、跳起来 | 眼睛睁大、嘴巴张开、身体前倾或带蹦跳动势 |

**不做的**：不新增物种、不新增阶段、不改现有 41 张基础图（`<species>-stageN.png` 保持原样）。

## 2. 输出路径与命名（必须完全一致）

```
electron-app/src/assets/pets/<species>/<species>-stage<1..5>-<expr>.png
```

- `<species>` ∈ `cat dog bunny hamster bird deer fish fox`（8 种）
- `<expr>` ∈ `pat feed play`（3 种）
- 共 **8 × 5 × 3 = 120 张**
- 例：`electron-app/src/assets/pets/cat/cat-stage3-pat.png`

> `design/` 下的两份页面用 `../electron-app/src/assets/…` 前缀，指向同一个目录，**不需要**另出一份。

## 3. 画布与风格（与现有图一致才不违和）

- 尺寸：**512×512**，透明背景（PNG-32 / RGBA）
- 主体：与对应的 `<species>-stageN.png` **同一只宠物、同一姿态基准、同一描边粗细与配色**；只改脸部（眼/嘴/腮红）与必要的头部小动作，身体与构图不要漂移
- 画风：手绘墨线（1.5–2px 深墨描边）+ 纸质/牛皮纸暖色系，扁平上色，不使用渐变光泽、不用 3D、不加文字水印
- 留白：宠物主体占画布 **60%–75%**，四周至少 40px 透明边距（与现有图一致，避免卡片里被裁）
- 单张体积建议 ≤ 250KB

## 4. 给豆包的提示词模板（逐张替换变量）

```
参考图：<species>-stage<N>.png（必须先上传这张作为参考，保持同一只宠物与同一姿态）
任务：在同一只宠物、同一构图、同一描边与配色的基础上，只改表情。
表情：<pat=舒服眯眼被摸头 / feed=满足吃零食 / play=兴奋跳起来>
要求：512×512、透明背景、手绘墨线描边 1.5-2px、扁平上色、主体占 60%-75%、四周≥40px 透明边距、不要文字与水印。
输出文件名：<species>-stage<N>-<expr>.png
```

一次批量时可用下面的清单逐条执行（先做完 cat 的 15 张看效果，再推其余 7 种）：

```
物种：cat
阶段：1,2,3,4,5
表情：pat,feed,play
```

## 5. 交付校验（我用来判定合格，不需要眼睛）

```bash
node scripts/validate_pet_expressions.js            # 全量检查（缺图/尺寸/透明通道/命名/体积）
node scripts/validate_pet_expressions.js --species cat   # 只看某个物种
```

校验内容：
1. 三份集合（物种 × 阶段 × 表情）是否齐全，缺哪张逐条列出；
2. 是否真 PNG、宽高是否 512×512；
3. PNG 颜色类型是否带 alpha（RGBA / 调色板带 tRNS）；
4. 单张是否 ≤ 250KB；
5. 是否有多余/命名不符的文件。

> 通过标准：`missing=0 errors=0`。代码在缺图时会自动退回基础图，所以**分批交付也能直接上线**。

## 6. 上线后的效果

- 点宠物 → 三个圆圈（摸摸/喂食/玩耍）→ 点其中一个：宠物换成对应表情图 2.5 秒后还原，同时弹出随机一句反应气泡；
- 每个互动按学生有 **20 秒冷却**（按钮显示剩余秒数），不写数据库、不加经验；
- 表情图缺失时：只出气泡，不报错。
