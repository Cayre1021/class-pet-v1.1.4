# V3 前后端对齐表

> 记录 V3 三页与 `classpet_core.js` / `preload.js` / `main.js` / `sqlite_service.js` / SQLite 的真实对应关系。
> 依据：2026-11-19 的代码（提交 `f1468c2` 起）。改动后请同步本表。

## 一、分层与调用链

```
三页 HTML（design/ 为源，electron-app/src/ 为镜像）
  └─ window.classPetRuntime（classpet_core.js，动态注入，仅在有 preload 时加载）
       └─ window.electronAPI.db.*（preload.js，contextBridge）
            └─ ipcMain.handle('db:*')（main.js）
                 └─ SQLiteService（sqlite_service.js，sql.js）
                      └─ database/classpet.sqlite → 运行时落在 userData/classpet.sqlite
```

- 浏览器直开（无 preload）时 `window.electronAPI` 为 `undefined` → 三页进入**演示态**（不读库、不写库）。
- `classpet_core.js` 用 `<script src="classpet_core.js">` 动态注入；教师台 CSP 因此需要 `script-src 'unsafe-inline' file:`。

## 二、IPC 通道 → 服务方法

| preload 方法 | IPC 通道 | SQLiteService 方法 | 说明 |
|---|---|---|---|
| `db.loadAllState` | `db:loadAllState` | `loadAllState` | 读全班：学生/宠物/规则/阈值/形态/最近 50 笔操作 |
| `db.recordScore` | `db:recordScore` | `recordScoreOperation` | 赋分事务：`score_operations`+`score_entries`+更新宠物；无该科宠物时拒单 `NO_PET_FOR_SUBJECT` |
| `db.undoScore` | `db:undoScore` | `undoOperation` | 撤销；**只允许本班最后一笔未撤销操作**（`NOT_LAST`） |
| `db.hatchPet` | `db:hatchPet` | `hatchStudentPet` | 破壳；门槛：学生存在/未破壳/经验≥库内 1 级阈值/学科已解锁 |
| `db.saveStudent` | `db:saveStudent` | `saveStudent` | 单人 upsert（含三科宠物） |
| `db.updateStudentProfile` | `db:updateStudentProfile` | `updateStudentProfile` | **只改姓名/小组**，不碰等级经验物种 |
| `db.getClassLedger` | `db:getClassLedger` | `getClassLedger` | 台账（按时间范围；含学生/学科/撤销状态/前后经验） |
| `db.restoreClassBackup` | `db:restoreClassBackup` | `restoreClassBackup` | 整包恢复（学生+宠物+阈值+形态+规则同一事务） |
| `db.saveThresholds` | `db:saveThresholds` | `saveThresholds` | 21 级阈值 + 6 段形态 |
| `db.saveBehaviorRules` | `db:saveBehaviorRules` | `saveBehaviorRules` | 行为规则整表保存 |
| `db.getStudentAuditLogs` | `db:getStudentAuditLogs` | `getStudentAuditLogs` | 单人审计流水（旧页面在用） |
| `db.importStudents` / `db.saveAllStudents` | 同名 | 同名 | 整班导入/批量同步（V3 页面**不使用** `importStudents` 做 CSV 导入，见下） |
| `db.archiveStudent` / `db.deleteStudent` | 同名 | 同名 | 归档/删除（按 D2：归档留服务不留界面） |
| `db.query` / `db.execute` | 同名 | 同名 | 通用读写（V3 仅 core 用它做「最后一笔」精确查询） |
| `toggleFullscreen` / `openDisplayWindow` / `openTeacherWindow` / `openPortalWindow` | 同名 `send` | — | 单窗口原地跳转（三页互跳统一走它） |

| `v3RestoreBackup(payload)`（`1256`） | `db.restoreClassBackup` | — | ✅ JSON 备份恢复 | — |

前端未走 core、直连 preload 的两处（有意为之）：
1. **CSV 导入**：教师台逐人调 `db.saveStudent`（upsert 语义，**不删除**文件里没有的学生）；不走 `db.importStudents`（那个是整班删除重建，CSV 漏行会真删人）。
2. **台账清空**：真实态只清页面内记忆，不动库。

## 四、数据契约要点（谁说了算）

| 事实 | 唯一来源 | 备注 |
|---|---|---|
| 等级 | `class_level_thresholds` + 宠物 `exp` | 由 `calcLevel` 推导，页面不再 `ceil(level/2)` |
| 形态（stage） | `class_visual_stages`（`STAGE_MIN_LEVELS`） | 只升不降，取「已获得形态」与「按等级推导」的较大值 |
| 形态名 | `STAGE_MIN_LEVELS[idx].name` | 三页同一套名字 |
| 卡片展示宠 | `students.display_pet_id` | D7=A：切授课科目不换宠 |
| 当前授课科目 | `localStorage.classpet_current_teaching_subject` | 只决定赋分目标 |
| 身份（classId/teacherId） | `localStorage.classpet_current_account` → `classpet.teacher.profile.v3` | D13=A：姓名不当身份 |
| 缺勤 | 页面会话内开关 | D9=A：不落历史，读库恒 false |
| 行为规则 | `behavior_rules` | 真实库现有 13 条，赋分台按库渲染 |
| 备份格式 | `{kind:'classpet-class-backup',version:1,...}` | 版本不支持/重复 id 一律拒绝 |

## 五、已知缺口（都未擅自补）

| 缺口 | 现状 | 影响 |
|---|---|---|
| 教师台「调整分组」入口 | `openMoveGroupDialog()` **无调用点**；这是**已签决策 D1=A + DESIGN_SPEC §12 第 1 条**「移组入口确认取消」的结果，不是遗漏 | 批量移组不可用（单人改组走「编辑资料」）；代码里保留真实态分支并已加注说明，**不要据"无入口"判定为缺陷再提** |
| 学生大屏撤销 | 本页无撤销入口（负责人 2026-11-19 确认不加） | 撤销只在教师台 |
| 归档 | 按 D2 留服务不留界面 | 库里有 `archived_at`，VM 透出 `isArchived`，页面不过滤展示 |
| 考勤 | D9=A 会话内开关 | 重启恢复默认 |
| `storage` 跨文档同步 | file:// 下 Chromium 不派发该事件 | 主题/音效切页后一致，但同屏双窗口实时同步未验证 |
