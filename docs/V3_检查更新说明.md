# V3 · 检查更新（GitHub Releases）说明

_最后更新：2026-11-20_

## 一、老师在哪儿用

教师操作台 →「数据与设置」→「**检查更新**」（菜单项右侧显示当前版本号）。

- **进教师台时静默查一次**：主进程每天最多真正请求一次（24h 缓存），有新版本只在「数据与设置」按钮上挂一个小红点，**不弹窗、不打断上课**；
- **手动点开**：立刻强制检查一次，弹纸感弹窗显示「当前版本 → 最新版本 / 安装包名与体积 / 更新说明」。

三种结果都有明确反馈：

| 情况 | 表现 |
|---|---|
| 有新版本 | 弹窗 + 「下载新版本」「打开发布页」两个按钮；点下载用**系统浏览器**打开安装包地址 |
| 已是最新 | 只弹一句 toast：已是最新版本 vX（今天查过会提示"今天已经查过"） |
| 连不上 / 限流 / 仓库没有发布 | 弹窗说明中文原因 + 「重试」「打开发布页」 |

**不做自动安装**：安装包由老师双击安装（应用无代码签名，静默安装会被 Windows/SmartScreen 拦）。

## 二、数据与安全

- 只发一个 GET 请求到 GitHub API（或自定义更新源），**不上传任何班级数据**；
- 打开的下载地址有白名单：只允许 `github.com` / `objects.githubusercontent.com` 等主机，其它域名一律拒绝；
- 检查失败不影响上课：静默检查的异常全部吞掉，只留手动入口。

## 三、可达性（重要，实测）

在开发机（中国大陆网络）实测：

```
api.github.com  ->  ECONNRESET（约 5 秒超时）
```

也就是说**大陆教室直连 GitHub 大概率查不到更新**，界面会显示「连不上 GitHub：请检查网络…」。这不是 bug，是网络现实。

### 换源的两种办法（都不用改代码）

1. **换仓库**：环境变量 `CLASSPET_UPDATE_REPO=owner/repo`；
2. **换更新源（推荐长期方案）**：环境变量 `CLASSPET_UPDATE_FEED=https://你的域名/latest.json`
   —— 把安装包和一个小 JSON 放在国内对象存储（阿里云 OSS / 腾讯云 COS / 七牛 / R2 + 自定义域名），速度稳定；

   `latest.json` 两种写法都支持：

   ```json
   { "version": "1.3.0",
     "url": "https://cdn.example.com/ClassPet%20Setup%201.3.0.exe",
     "notes": "· 修复宠物表情残留\n· 新增检查更新",
     "size": 120000000,
     "pageUrl": "https://example.com/releases" }
   ```

   ```json
   { "tag_name": "v1.3.0", "body": "更新说明", "assets": [ { "name": "ClassPet Setup 1.3.0.exe", "browser_download_url": "https://...", "size": 120000000 } ] }
   ```

   设置方式：在启动脚本里 `set CLASSPET_UPDATE_FEED=...`，或写进系统环境变量。

## 五、以后要发新版本，怎么发

1. 改 `electron-app/package.json` 的 `version`（例：1.2.0 → 1.3.0）；
2. `npm run dist:win` 重新打包；
3. 把安装包上传到 GitHub Releases（或更新源的目录），用 tag `v1.3.0`，说明写进 release body；
4. 老师那边下次进教师台就会看到红点。

### 阻塞点 1：仓库是私有的

```
GET https://api.github.com/repos/Cayre1021/class-pet-v1.1.4/releases/latest  ->  HTTP 404（1.6s）
gh api repos/Cayre1021/class-pet-v1.1.4 --jq .private                            ->  true
```

私有仓库的 Release **匿名访问一律 404**。客户端不能内置 token（会泄漏），所以三条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| ① 仓库转公开 | GitHub → Settings → General → Danger Zone → Change visibility → Public | 源码公开 |
| ② 建一个**只放安装包**的公开仓库 | 如 `class-pet-releases`，只上传 exe；设 `CLASSPET_UPDATE_REPO=你的账号/class-pet-releases` | 需要维护第二个仓库；源码仍私有 |
| ③ 换自定义更新源 | 安装包 + `latest.json` 放 OSS/COS/七牛，设 `CLASSPET_UPDATE_FEED=https://…/latest.json` | 需要对象存储 |

### 资产上传实操（2026-11-20 18:4x，两个资产都在线）

| 资产 | 大小 | 状态 |
|---|---|---|
| `ClassPet.Setup.1.2.1.exe` | 120,536,390 B（115.0 MB） | uploaded |
| `ClassPet-Portable-1.2.1.exe` | 120,303,892 B（114.7 MB） | uploaded |

匿名 `GET releases/latest` -> 200，两个资产都在；App 以 1.2.0 检查会自动选中 Setup 安装版。

**踩过的坑（务必记住）**

1. `gh release upload` 在慢网/断网上会报 `HTTP 408 Upload body timed out`，且被中断的资产会停在 `state: "starter"`；
   **starter 状态的资产不会出现在 `releases/latest` 里**，看起来像"资产消失了"。
2. 正确姿势：**用 curl 直传**，并在每次重试前用 API 删掉 starter：
   ```bash
   # 列出并清理半成品
   gh api repos/<owner>/<repo>/releases/<release_id>/assets --jq '.[] | select(.state=="starter") | .id'
   gh api -X DELETE repos/<owner>/<repo>/releases/assets/<asset_id>
   # 直传（成功返回 201，状态才是 uploaded）
   curl -sS -X POST -H "Authorization: Bearer $GH_TOKEN" -H "Content-Type: application/octet-stream" \
        --data-binary @"electron-app/release/ClassPet-Portable-1.2.1.exe" \
        "https://uploads.github.com/repos/<owner>/<repo>/releases/<release_id>/assets?name=ClassPet-Portable-1.2.1.exe&label=免安装便携版"
   ```
3. 验证标准：`state == "uploaded"` **且** `size` 与本地文件字节数一致 —— 只看 HTTP 200/201 不够。
4. 开发机上 `github.com/.../releases/download/...` 的 HEAD 会出现 `ECONNRESET`（API 正常）。
   即"能查版本、但下载链接可能连不上"，这正是 `CLASPET_UPDATE_FEED` 国内镜像存在的意义。
### 决策记录（2026-11-20，负责人）

- **不开通任何云服务**，更新源就用 GitHub Releases（当前唯一 Release：`v1.2.1`，两个资产均已 uploaded）。
- 因此 `CLASPET_UPDATE_FEED` 国内镜像留作"以后想用再开"的开关，代码支持、默认不启用，不产生任何额外成本。
- 网络不通时的既定体验（已实现，无需改代码）：
  - 静默检查失败：不打扰上课，菜单不挂红点；
  - 手动检查失败：弹窗说明「连不上 GitHub…可稍后用手机热点或换网络再试」，并提供「重试」「打开发布页」。
- 分发约定：只发 `1.2.1`（Setup / Portable）；`release\_broken\` 里的 1.2.0 一律作废，装了 1.2.0 的机器需用 1.2.1 覆盖安装。
