## 二、硬事实：原型与真实实现的数据模型并不一致

真实库在 `electron-app/sqlite_service.js`，IPC 通道在 `electron-app/main.js`。已核对：

**表**：`classes` `teachers` `students` `pets` `subjects` `behavior_rules` `score_entries` `score_operations` `class_level_thresholds` `class_visual_stages`

**通道**：`db:loadAllState` `db:saveStudent` `db:deleteStudent` `db:archiveStudent` `db:recordScore` `db:undoScore` `db:hatchPet` `db:importStudents` `db:saveAllStudents` `db:saveBehaviorRules` `db:saveThresholds` `db:getStudentAuditLogs` `db:query` `db:execute`；窗口类 `open-portal-window` `open-teacher-window` `open-display-window` `get-displays` `toggle-fullscreen` `broadcast-sync`

### 必须逐条确认的差距（P0 的核心产出）

| # | 差异 | 真实实现 | 原型 | 处理方向 |
|---|---|---|---|---|
| 1 | 等级体系 | 0–20 级，`class_level_thresholds` 最小经验 0…1250 | LV1–9，`level*40` | 等级徽章文案（LV.n）与进度按**真实阈值**算；卡面只显示等级数字，不写死 9 级上限 |
| 2 | 阶段/形态 | `class_visual_stages`：egg / form1(1) / form2(4) / form3(8) / form4(13) / form5(20) | `ceil(level/2)` 或 `level-2` | 用 `visual_stage` 直接选图，不再自己算 |
| 3 | 学科 | `subjects` 表 + `pets.subject_id`，一个学生可有多科宠物 | 单学科，科目是顶栏/赋分台的全局开关 | **最大结构性差距**：需决定「卡片显示哪只宠物」（建议：`display_pet_id`；切换学科=切换显示的那只） |
| 4 | 赋分规则 | `behavior_rules`（含 sort_order、正负分） | 教师台硬编码 6 条 + 自定义规则存内存 | 改为从 `loadAllState` 读规则渲染按钮；自定义规则写回 `db:saveBehaviorRules` |
| 5 | 归档 | `students.archived_at` + `db:archiveStudent` | 界面入口已按需求全部删除 | **需产品确认**：能力保留但无入口，还是连通道一起废弃 |
| 6 | 印章 | `score_entries` 可按规则统计 | 已从界面删除 | 同上：确认是否彻底废弃，还是后台保留统计 |
| 7 | 登录 | `teachers` / `classes` 表 + 既有 `portal_auth.html` | localStorage 存 {班级, 姓名, 科目} | 入口页登录要与既有账号体系打通；`class_id` 必须带下去 |
| 8 | 实时同步 | `broadcast-sync` | 三页各自独立 | 赋分后大屏要同步刷新（监听 broadcast-sync 重渲染） |

## 三、路线（按周，P0→P3）

### P0 · 对齐表 + 冻结视觉（3–4 天）
产出 `docs/V3_前后端对齐表.md`：**每个可点元素 → 触发的 IPC → 需要的字段 → 缺口 → 结论**。要求：
- 覆盖教师台全部控件（搜索/新增/编辑/日志/赋分/撤销/台账/CSV/阈值/备份/主题/音效/全屏/重置/返回）；
- 覆盖学生大屏全部交互（点卡/检查器/赋分/破壳/悬浮球四项/换肤/排序）；
- 覆盖入口页（注册、登录、退出、切换账号、两个入口）。
- 每个「缺口」必须给出三选一：**改前端适配真实数据 / 改后端补字段 / 产品确认不做**。
- 验收：表格里没有"待定"项；差异 1–8 全部有结论。

### P1 · 接线（1–1.5 周）
- 教师台：`loadAllState` 驱动渲染；赋分走 `db:recordScore`，撤销走 `db:undoScore`；新增/编辑走 `db:saveStudent`；台账走 `db:getStudentAuditLogs`；阈值走 `db:saveThresholds`。
- 学生大屏：只读 `loadAllState` + 监听 `broadcast-sync`；破壳走 `db:hatchPet`。
- 入口页：接真实登录，成功后按 `class_id` 打开对应窗口（`open-teacher-window` / `open-display-window`）。
- 验收：**不接真实班级库**，用隔离测试库（`Open-ClassPet-Test.cmd`）跑通：注册→登录→进教师台→选 3 人赋分→回大屏看到同步→撤销→台账有一笔。

### P2 · 回归与视觉锁定（3–5 天）
- `__v3audit()` 必须继续 `pass=true`（这是冻结视觉的护栏，改样式前先跑）；
- 三页两视口文档不滚动、遮挡 0、弹窗无滚动条；
- 真实数据下 32 人以上（建议用 88 人）验证：网格滚动、卡片不抖动、检查器不盖卡。

### P3 · 打包与交付（2–3 天）
- 只替换前端资源，不动 SQLite 结构与发布配置；打包前备份数据；
- 交付物：可运行包 + 对齐表 + 回归清单 + 回滚方式。

## 四、给接手同学的第一周清单（可直接当任务派）

1. 读 `design/V3_DESIGN_SPEC.md`（契约）→ 读 `sqlite_service.js` 的 `loadAllState` → 读 `main.js` 的 IPC 注册。
2. 跑一次 `scripts/audit_all.js` 与 `audit_v3_pages.js`，确认你本地基线和我给的一致（这是后面判断"有没有改坏"的唯一尺子）。
3. 产出 `docs/V3_前后端对齐表.md`（P0），四个差异点必须给出结论：**学科、等级/阶段、归档、印章**。
4. 用隔离库接一条最小链路：**教师台渲染真实名单 → 点 +3 → 写库 → 学生大屏刷新看到变化**。
5. 回来对齐：确认 P1 的窗口/通道划分没有异议，再全量接线。

## 五、红线（违反任何一条都要先停下来问）

- 界面**视觉与信息架构已冻结**（上级已认可）：不得以"适配数据"为由改布局、删入口、改字号间距。真需要改，先改 `V3_DESIGN_SPEC.md` 并单独确认。
- 不得绕过 preload/IPC 直接读 SQLite；不得在页面里写库路径。
- 不得对正式班级库做写操作；测试一律用 `Open-ClassPet-Test.cmd` 的隔离库，写前备份。
- 不得删除既有功能入口（门户返回、学生大屏、搜索、新增、编辑、日志、赋分、撤销、台账、Excel、阈值、备份、主题、音效、全屏、重置）。
- 不得把 `localStorage` 里的演示档案当成真实账号体系。

## 六、风险提示

| 风险 | 影响 | 缓解 |
|---|---|---|
| 学科/多宠物模型与原型不一致 | 卡片显示哪只宠物说不清 | P0 必须先定，建议用 `display_pet_id` + 学科切换=切显示宠 |
| 等级 0–20 与原型 9 级 | 徽章文案、进度条、阶段图全要重算 | 一律读 `loadAllState` 的阈值，前端不写死 |
| 赋分规则来自库 | 按钮数量不固定，380px 侧栏可能溢出 | 已内置滚动区。行 + 「还有 N 项」提示，规则变多不会坏 |
| 大屏同步延迟 | 老师赋分后大屏不动 | 接 `broadcast-sync`；验收项里必须有"同步"这一条 |
| 归档/印章已从界面删除 | 后台仍有数据 | P0 给结论：保留统计或一并废弃，不要半留半删 |
